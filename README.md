# Spending Limit Service

Микросервис банка для учёта расходных операций клиентов и месячных лимитов в USD.

Сервис принимает транзакции в тенге, рублях и долларах, пересчитывает их в USD по биржевому курсу закрытия дня
(Twelve Data), ведёт месячные лимиты отдельно для товаров и услуг и помечает транзакции, превысившие лимит
(`limit_exceeded`). Клиентский API позволяет установить новый лимит, посмотреть все лимиты и получить
транзакции, превысившие лимит, вместе с данными этого лимита.

**Стек:** Java 21, Spring Boot 4.1 (Web MVC на виртуальных потоках), Spring Data JPA / Hibernate 7,
PostgreSQL 18, Flyway, MapStruct, Jackson 3, springdoc-openapi, Logbook, Micrometer / Prometheus,
JUnit 5, Testcontainers, WireMock, ArchUnit, JaCoCo, Docker, GitHub Actions.

## Быстрый старт

### Весь сервис с базой одной командой

```bash
docker compose up --build
```

- Swagger UI: http://localhost:8080/swagger-ui.html, OpenAPI: http://localhost:8080/v3/api-docs
- Без ключа API используются фиксированные курсы (450 KZT и 75 RUB за 1 USD).
  Для настоящих курсов скопируйте `.env.example` в `.env` и задайте `RATES_PROVIDER=twelvedata`
  и `TWELVEDATA_API_KEY` (бесплатный ключ: https://twelvedata.com).
- Первая сборка образа скачивает зависимости Maven и занимает несколько минут.

### Локально для разработки

```bash
docker compose up -d postgres
```

```bash
./mvnw spring-boot:run
```

Профиль `dev` включён по умолчанию: подключение к базе из `docker-compose.yml`, фиксированные курсы.
Для настоящих курсов задайте переменные `RATES_PROVIDER=twelvedata` и `TWELVEDATA_API_KEY`.

### Тесты

```bash
./mvnw verify
```

Нужен только запущенный Docker. Команда выполняет unit-тесты (`*Test`), интеграционные и сквозные тесты
(`*IT`) с PostgreSQL в Testcontainers и Twelve Data, подменённым WireMock, проверку архитектуры (ArchUnit)
и порог покрытия доменных пакетов (JaCoCo: строки ≥ 90 %, ветви ≥ 85 %).

## API

| API | Запрос | Назначение | Ответы |
|---|---|---|---|
| Интеграционный | `POST /api/integration/v1/transactions` | Принять транзакцию | 201 обработана, 202 ждёт курса, 400, 422 |
| Клиентский | `POST /api/client/v1/limits` | Установить новый лимит | 201, 400, 409 |
| Клиентский | `GET /api/client/v1/limits?account=` | Все лимиты счёта со статистикой | 200, 400 |
| Клиентский | `GET /api/client/v1/transactions/limit-exceeded?account=&page=&size=` | Транзакции, превысившие лимит | 200, 400 |

Транзакция:

```bash
curl -X POST localhost:8080/api/integration/v1/transactions -H "Content-Type: application/json" -d '{"account_from": "0000000123", "account_to": "9999999999", "currency_shortname": "KZT", "sum": 10000.45, "expense_category": "product", "datetime": "2022-01-30T00:00:00+06:00"}'
```

```json
{"id": 1, "status": "processed", "sum_usd": 22.22, "limit_exceeded": false}
```

Новый лимит (дата устанавливается сервисом):

```bash
curl -X POST localhost:8080/api/client/v1/limits -H "Content-Type: application/json" -d '{"account": "0000000123", "expense_category": "product", "limit_sum": 2000.00}'
```

Транзакции, превысившие лимит:

```bash
curl "localhost:8080/api/client/v1/transactions/limit-exceeded?account=0000000123"
```

```json
[{"account_from": "0000000123", "account_to": "9999999999", "currency_shortname": "KZT", "sum": 270000.00,
  "expense_category": "product", "datetime": "2022-01-03T12:00:00+06:00",
  "limit_sum": 1000.00, "limit_datetime": "2022-01-01T00:00:00Z", "limit_currency_shortname": "USD"}]
```

JSON в формате snake_case. Неизвестные поля, число вместо строки и наоборот, сумма с тремя знаками после
запятой отклоняются с 400. Все ошибки возвращаются в формате RFC 9457 (`application/problem+json`):

```json
{"detail": "Request validation failed", "instance": "/api/client/v1/limits", "status": 400, "title": "Bad Request",
 "errors": [{"field": "account", "message": "must consist of exactly 10 digits"}]}
```

## Бизнес-правила

- **Остаток лимита** = сумма действующего лимита − все траты счёта в этой категории за месяц в USD,
  включая текущую транзакцию. `limit_exceeded = true`, только если остаток **меньше нуля**: потратить лимит
  ровно до нуля можно.
- **Действующий лимит** транзакции — последний лимит, установленный клиентом не позже момента транзакции.
  Новый лимит не меняет флаги уже обработанных транзакций. Траты месяца, сделанные до установки нового лимита,
  учитываются: лимит 2000 USD, установленный после трат на 1100 USD, оставляет 900 USD.
- **Лимит по умолчанию** — 1000 USD (`app.limits.default-amount`). Он создаётся при первой транзакции счёта
  и категории без клиентского лимита; его дата — момент этой транзакции.
- **Дата лимита** всегда текущее время сервиса: передать её нельзя (400), прошлую или будущую дату установить
  невозможно. Лимиты не изменяются: в API нет изменения, а в БД изменение и удаление запрещены триггером.
- **Часовой пояс.** Месяцы и дни считаются в одном поясе — **UTC** (переменная `BUSINESS_ZONE`).
  Транзакция `2022-02-01T03:00:00+06:00` — это 31 января 21:00 UTC, она относится к январю и к курсу 31 января.
  В ответах дата транзакции возвращается с тем смещением, с которым пришла.
- **Курсы.** Используется курс закрытия (`close`) дня транзакции, а если торгов не было (выходной, праздник) —
  последний курс закрытия перед ним (`previous close`). Курс хранится как число единиц валюты за 1 USD;
  сумма в USD = сумма / курс с одним округлением до центов (банковское, `HALF_EVEN`). Для USD курс не нужен.
- Транзакция, датированная позже текущего времени более чем на 5 минут, отклоняется (422), как и валюта
  вне `app.rates.supported-currencies` (по умолчанию KZT, RUB и USD).

## Сбои внешнего API

Приём транзакций устроен так, чтобы сбой Twelve Data не терял данные и не задерживал ответ дольше пары секунд.

1. Транзакция **сохраняется в БД до любых внешних вызовов**.
2. Курс берётся **сначала из своей БД**. К Twelve Data сервис обращается только за днём, которого ещё нет:
   одним запросом за 10 предыдущих дней, и сохраняет всё полученное. Каждый день оплачивается один раз,
   одновременные запросы одного дня объединяются в один HTTP-запрос.
3. **Таймауты:** соединение 2 с, ответ 3 с.
4. **Повторы:** временные сбои (HTTP 5xx, 429 — и в статусе, и в теле ответа при HTTP 200, обрыв соединения)
   повторяются сразу 2 раза с паузой 200 и 400 мс. Таймаут и ошибки 4xx не повторяются: медленный провайдер
   заставил бы ждать несколько таймаутов подряд.
5. Если курс получить не удалось, транзакция остаётся в статусе **PENDING**, клиент получает **202**.
   Фоновая задача раз в 30 секунд дообрабатывает такие транзакции с растущим интервалом (30 с, 1 мин, 2 мин…
   до 1 ч). Несколько экземпляров сервиса не возьмут одну транзакцию: выборка `FOR UPDATE SKIP LOCKED` с арендой.
6. Курсы всех валют ежедневно в 00:05 загружаются заранее, параллельно на виртуальных потоках.

Курс текущего дня фиксируется при первом запросе и больше не меняется, поэтому все транзакции дня
пересчитываются по одному курсу.

## Одновременные транзакции

Транзакции одного клиента могут приходить параллельно. Обработка идёт в одной транзакции БД под блокировками
`SELECT ... FOR UPDATE` строки транзакции и строки месячных трат (счёт, категория, месяц), поэтому два запроса
не видят один и тот же остаток, а одна транзакция не учитывается дважды. Ожидание блокировки ограничено
`lock_timeout` (5 с). HTTP-запрос к провайдеру курсов делается до этого, вне транзакции БД.
Фоновая дообработка обрабатывает группы (счёт, категория, месяц) параллельно, а транзакции внутри группы —
по порядку времени.

## Архитектура

```
com.evlarus.spendinglimit
├── common        общие value objects (Money, AccountNumber, BusinessCalendar), обработка ошибок, конфигурация
├── limit         лимиты и месячные траты
├── rate          курсы валют и клиент Twelve Data
└── transaction   приём, обработка, дообработка и отчёт
      ├── api             контроллеры, DTO, MapStruct-мапперы
      ├── application     сценарии использования и порты внешних систем
      ├── domain          бизнес-правила на чистой Java и порты репозиториев
      └── infrastructure  JPA-сущности, адаптеры репозиториев, SQL-запросы, HTTP-клиент
```

- Бизнес-правила — в методах доменных классов: `MonthlySpending.register` считает остаток и флаг,
  `Transaction.process` переводит в USD и фиксирует результат один раз, `ExchangeRate.select` выбирает курс.
- Доменный слой не зависит от Spring, JPA и Jackson; JPA-сущности отделены от доменных объектов;
  объекты ссылаются друг на друга по id. Правила проверяет ArchUnit (`ArchitectureTest`).
- Чтение для API выполняется одним SQL-запросом; тесты считают число запросов (`QueryCounter`).

## Модель данных

Схема задаётся миграциями Flyway (`src/main/resources/db/migration`), Hibernate только сверяет сущности
со схемой (`ddl-auto=validate`).

| Таблица | Назначение |
|---|---|
| `spending_limit` | лимиты в USD по счёту и категории; неизменяемы (триггер) |
| `monthly_spending` | траты в USD по счёту, категории и месяцу; строка блокировки при проверке лимита |
| `exchange_rate` | курсы закрытия по валюте и дню |
| `bank_transaction` | транзакции, их статус, сумма в USD, применённый лимит и флаг |

Инварианты продублированы в БД ограничениями `CHECK`: формат счёта, положительная сумма, у обработанной
транзакции обязательно есть сумма в USD, лимит и флаг.

Список лимитов со статистикой (`JdbcLimitUsageQuery`) — запрос с **JOIN на подзапрос с агрегатными функциями
и группировкой** (`COUNT`, `COUNT ... FILTER`, `SUM`, `GROUP BY limit_id`). Отчёт о превышениях
(`JpaExceededTransactionsQuery`) — один JPQL-запрос с JOIN на применённый лимит.

## Конфигурация

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `SPRING_PROFILES_ACTIVE` | `dev` | `dev` — локальные настройки и фиксированные курсы; `prod` — всё из переменных, JSON-логи |
| `DB_URL`, `DB_USERNAME`, `DB_PASSWORD` | в `dev` — база из `docker-compose.yml` | подключение к PostgreSQL; в `prod` обязательны |
| `DB_NAME`, `DB_PORT` | `spending_limits`, `5432` | база для `docker-compose.yml` и профиля `dev` |
| `RATES_PROVIDER` | `twelvedata`, в `dev` и Docker Compose — `fixed` | источник курсов |
| `TWELVEDATA_API_KEY` | — | ключ Twelve Data; без него профиль `prod` с `twelvedata` не запускается |
| `BUSINESS_ZONE` | `UTC` | пояс, в котором считаются месяцы и дни |
| `DB_LOCK_TIMEOUT` | `5s` | сколько ждать заблокированную строку |
| `SERVER_PORT` | `8080` | порт HTTP |
| `MCP_DB_PASSWORD` | `mcp_readonly` | пароль локального пользователя `mcp_readonly` для MCP-сервера |

Прочие настройки — в `src/main/resources/application.yml` (`app.*`, `spring.http.serviceclient.twelvedata.*`).

## Наблюдаемость

- Логи: в `dev` — читаемые, в `prod` — JSON (ECS), `src/main/resources/logback-spring.xml`. HTTP-запросы
  и ответы, включая вызовы Twelve Data, пишет Logbook; номера счетов и заголовок `Authorization` маскируются.
- Actuator: `/actuator/health` (с `liveness` и `readiness`), `/actuator/metrics`, `/actuator/prometheus`.
- Метрики: `transactions.processed{limit_exceeded}`, `transactions.pending`,
  `exchange_rate.lookups{source}`, `http.client.requests` для Twelve Data.

## Тесты

- **Доменные unit-тесты** — правила лимитов, курсов и транзакций, включая оба случая из таблицы задания
  построчно (`SpecificationScenariosTest`) и граничные случаи: остаток ровно 0, смена лимита внутри месяца,
  переход на новый месяц, граница месяца в разных поясах.
- **Web-тесты** (`@WebMvcTest`) — валидация, формат JSON и ошибок.
- **Интеграционные** — PostgreSQL в Testcontainers: блокировки и таймаут блокировки, параллельные транзакции
  одного счёта, повторная обработка, отчёт одним запросом, клиент Twelve Data с WireMock (повторы, таймауты,
  ошибки в теле ответа), маскирование логов, метрики.
- **Сквозной тест** `SpecificationScenariosE2EIT` поднимает приложение на случайном порту и только через HTTP
  воспроизводит «1 случай» из задания: лимиты 1 и 10 января 2022, транзакции в тенге, отчёт ровно с
  транзакциями 3 и 13 января и превышенными ими лимитами. Тем же способом проверяется «2 случай».
- CI (GitHub Actions) на каждый PR: `./mvnw verify` и сборка Docker-образа.

## MCP

`.mcp.json` подключает два MCP-сервера:

- **postgres** — [MCP Toolbox for Databases](https://mcp-toolbox.dev) с набором инструментов для PostgreSQL:
  агент видит схему, индексы и данные локальной базы. Подключение идёт под пользователем `mcp_readonly`
  только для чтения (его создаёт `docker/postgres/init/01-create-mcp-readonly-user.sh` при первом запуске
  контейнера). Пароль берётся из переменной `MCP_DB_PASSWORD`, по умолчанию — `mcp_readonly`, как в
  `docker-compose.yml`: это локальный пользователь только для чтения. Для уже созданной базы пользователь появится после `docker compose down -v`.
  Команда запуска рассчитана на Windows (`cmd /c npx …`); на macOS и Linux замените `"command": "cmd"`
  и первый аргумент `"/c"` на `"command": "npx"`.
- **context7** — актуальная документация по Spring Boot и библиотекам проекта.

Claude Code спрашивает разрешение на серверы из `.mcp.json` при первом запуске в проекте.
